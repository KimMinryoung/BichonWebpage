# CommuLingo data-only updates

The production container mounts host data (`-v /home/grass/frontend/data:/app/data`), so everything below is visible to the running app without rebuilding the image. **Never edit CommuLingo content values in code** — see the rule kept in `CLAUDE.md`, which stays in force here.

- For CommuLingo content-only edits in `data/commulingo/lessons.json` or `data/commulingo/courses/*.js`, do not run `scripts/deploy` just to rebuild/restart the frontend. Write the whole file and rename it into place (the container reads it live), run `node scripts/build-commulingo-shards.js` on the host so the container finds a matching digest instead of rebuilding mid-request, run `npm test` (the validator is in it; after fixing tolerated content run `node scripts/validate-commulingo.js --prune-baseline`), commit/push, verify the live API/page, then purge Cloudflare: `node scripts/changed-commulingo-lessons.js <old-ref> HEAD | node scripts/purge-commulingo.js --old-version <old-version> --stdin` (capture the old version first with `node -e "console.log(require('./data/commulingo/shards').currentVersion())"`). Capital chapters are rewritten with `scripts/commulingo-rewrite/` (see its README), not by hand.
- `routes/commulingo.js` loads CommuLingo through `data/commulingo/index.js` and caches the bundle by the maximum mtime across `lessons.json` and `courses/*.js`, so changed host data is picked up on the next request after mtime changes. Verify with `curl -s http://127.0.0.1:3000/commulingo/lesson/<lesson-id>`.
- CommuLingo reference documents (참고 문헌 전문) live in `data/commulingo/docs/` — `manifest.json` registry plus one HTML body fragment per doc; see `data/commulingo/docs/README.md` for the authoring rules. Adding/editing a document is data-only (mtime-cached): commit/push, then verify `/commulingo/docs/<id>`. The reader chrome lives in `views/public/commulingo-doc.ejs` + `public/css/commulingo-doc.css` (code — needs deploy).
- Merging a duplicate CommuLingo person (or renaming an office / role-category id) is DB-only: merge the rows, then `INSERT INTO commulingo_id_redirects (entity_type, from_id, to_id, note)` in the same transaction. The retired id starts 301ing to its target within one people-store refresh (~60s) — no commit, no rebuild. Chains (A→B→C) collapse to one hop at load time; a cycle drops the entry and logs it.
- 인물 상세 페이지의 절(`commulingo_person_sections`)은 `ORDER BY sort_order, id`로만 정렬된다. **`sort_order`는 그 절이 다루는 시기의 YYYYMM**(연도만 알면 MM=00: 1898 → `189800`, 1991년 8월 → `199108`)이라는 규약을 쓴다. 그래야 초년기 절을 나중에 써 넣어도 죽음 장면 아래로 밀리지 않는다. 값이 어긋나면 UPDATE 한 번으로 끝나고 배포도 커밋도 필요 없다(people-store 갱신 ~60초). 큐레이터 쪽 짝은 leninbot 저장소 `runtime_tools/commulingo_people.py`의 `_section_sort_order()` — `sortOrder`가 없으면 제목 속 연도를 YYYY00으로 쓰고, 그것도 없을 때만 맨 뒤에 붙인다.
- 러시아어 인명을 새로 등록할 때는 국립국어원 외래어 표기법의 러시아어 표를 따른다. `ш`는 `시`가 기본이고 뒤 모음과 합쳐 `ша`→`샤`, `ше`→`셰`, `ши`→`시`, `шо`→`쇼`, `шу`→`슈`가 된다. **`ш` 뒤에 자음이 오면 `시`를 유지한다**: `Штеменко`→`시테멘코`, `Шпигельглас`→`시피겔글라스`, `Шляпников`→`실랴프니코프`. 따라서 로마자 `Sh...`만 보고 습관적으로 `슈...`라고 쓰지 않는다. 다만 다른 언어에서 온 성이나 한국어 관용 표기가 확립된 이름은 원언어·기존 용례를 확인하고, 이미 인물 카드가 있으면 그 카드 표기를 우선한다. 신규 카드에서는 native name의 `Ш...` 형태와 한국어 이름·별칭을 나란히 대조한다.
- The CommuLingo registries that used to be arrays in code are tables, all read the way the dictionaries are (memory → on-disk snapshot → DB, 60s refresh) and all editable with one statement and no deploy: `commulingo_role_categories` (인물 역할 범주), `commulingo_term_categories` (용어 범주 — migration 115), `commulingo_link_blocklist` (자동링크 예외 — migration 116/117/154; 인물 패스는 `kind='phrase'`(별칭을 품은 문자열)·`kind='alias'`(성 한 단어를 아예 인덱싱하지 않음), 용어 패스는 `kind='term-phrase'`(복합어 차단, 예: 전세계→전세)·`kind='term-alias'`(중의적 별칭 제외 — 표제어는 살아남는다)·`kind='term-headword'`(표제어까지 차단, 예: 소비에트·전세; 영문은 대소문자 구분이라 케이스별로 행이 필요) — 전부 INSERT 한 번, 배포 불필요), `commulingo_id_redirects` (폐기 id). **전역이 아니라 한 페이지에서만 틀리는 링크**(프랑스 문서·사건의 임시정부)는 페이지 단위 제외를 쓴다: 참고 문헌은 `docs/manifest.json`의 `noAutoLink: ["임시정부"]`, 사건은 `commulingo_history_events.no_auto_link` jsonb 칼럼 — 둘 다 데이터 전용. 판별은 `docker exec leninbot-frontend node /app/scripts/audit-link-fires.js ko`로 그 별칭의 전 코퍼스 발화를 세어 보면 된다: 거의 다 틀리면 전역(term-alias/term-headword), 거의 다 맞고 한 페이지만 틀리면 noAutoLink. **용어 작명 규칙**(migration 155): 특정 상황·제도를 다루는 항목의 표제어는 구체적으로 짓고(한국전쟁 정전협정, 행동강령 (1968), 인민전선 (페레스트로이카)), 맨 일반형(정전협정, 행동강령)은 별칭으로 내린다 — 흔한 낱말을 표제어로 쓰면 그 낱말의 평범한 용례 전부가 그 항목으로 걸리는 오연결 부류가 태어난다. 항목 자체가 일반 개념인 경우(소비에트)만 예외. `commulingo_term_categories` also feeds the curator's tool schema in the leninbot repo, so a category added here is immediately writable by the agent.
- 한국어 시대 표기: 1948년 두 국가가 서기 전의 조선은 `조선`(1897~1910은 `대한제국`), 사람은 `조선인`, 말은 `조선어`다. `한국`은 1948년에 선 남쪽 국가의 이름이라 그 이전 문맥에는 쓰지 않는다(굳어진 예외는 `한국전쟁`). 영어 'Korea'를 시대 구분 없이 옮기면 얄타 회담의 주어가 한국이 되고 식민지 시기 문법서가 한국어 문법이 된다. `그루지야`처럼 일괄 치환할 수는 없다 — 재벌 체제·전세·1987년 체제 같은 현대 남한 항목에서는 `한국`이 맞기 때문이다. 그래서 문장의 연도를 읽어 판정하는 감사를 둔다: `docker exec leninbot-frontend node /app/scripts/audit-korea-terminology.js` (판정 규칙은 `data/commulingo/korean-terminology.js`, 사람이 판단해 남긴 예외는 감사 스크립트의 `KNOWN_OK`). 큐레이터·번역 프롬프트 쪽 짝은 leninbot 저장소의 `agents/commulingo_event_curator.py`, `scripts/commulingo_{events,people}_maintainer.py`, `runtime_tools/archival_translation/core.py`.
- **인물 등록·수정은 SQL이 아니라 Admin 스토어 경로로 한다**: `scripts/commulingo-people-upsert <spec.json> [--dry-run]` (스펙 형식은 `scripts/commulingo-people-upsert.js` 머리 주석; 컨테이너 안에서 `people-admin-store`를 그대로 호출하므로 `/admin/api/commulingo/people`과 같은 검증을 받는다 — 제 문자 이름·이름 분해·부칭 분리·국적 코드·**역할 필수**·**짧은 카드 라벨**). 손으로 쓴 `INSERT INTO commulingo_people`는 이 검증을 전부 비켜 가서 2026-09-05 167번(울메르: 역할 행 없음, fate 라벨이 문장, 출신 칸에 출생지)이 났다. 사후 보루는 `docker exec leninbot-frontend node /app/scripts/audit-person-card-fields.js`(역할 행·fate 길이·출생지 라벨, exit 1) — `audit-person-native-names.js`·`audit-person-patronymics.js`·`audit-person-name-order.js`와 함께 인물 관련 SQL을 손으로 돌린 뒤엔 반드시 넷 다 돌린다. 카드 라벨 규격: fate는 `옥사`·`전사`·`수용소에서 사망`처럼 짧게(연도는 `years`에 이미 있으므로 넣지 않는다, ko 24자·en 50자 초과는 거부), citizenship/nationalOrigin은 나라·민족 라벨(`에스토니아 (스웨덴계)`)이지 출생지가 아니며, `cyrillic`(제 문자 이름)에는 부칭을 넣지 않는다(부칭은 `patronymic`/`cyrillicPatronymic`). 규칙 본체는 `data/commulingo/person-card-validation.js` 한 곳.
