# CommuLingo data-only updates

The production container mounts host data (`-v /home/grass/frontend/data:/app/data`), so everything below is visible to the running app without rebuilding the image. **Never edit CommuLingo content values in code** — see the rule kept in `CLAUDE.md`, which stays in force here.

- For CommuLingo content-only edits in `data/commulingo/lessons.json` or `data/commulingo/courses/*.js`, do not run `scripts/deploy` just to rebuild/restart the frontend. Commit/push the data change, then verify the live API/page.
- `routes/commulingo.js` loads CommuLingo through `data/commulingo/index.js` and caches the bundle by the maximum mtime across `lessons.json` and `courses/*.js`, so changed host data is picked up on the next request after mtime changes. Verify with `curl -s http://127.0.0.1:3000/commulingo/lesson/<lesson-id>`.
- CommuLingo reference documents (참고 문헌 전문) live in `data/commulingo/docs/` — `manifest.json` registry plus one HTML body fragment per doc; see `data/commulingo/docs/README.md` for the authoring rules. Adding/editing a document is data-only (mtime-cached): commit/push, then verify `/commulingo/docs/<id>`. The reader chrome lives in `views/public/commulingo-doc.ejs` + `public/css/commulingo-doc.css` (code — needs deploy).
- Merging a duplicate CommuLingo person (or renaming an office / role-category id) is DB-only: merge the rows, then `INSERT INTO commulingo_id_redirects (entity_type, from_id, to_id, note)` in the same transaction. The retired id starts 301ing to its target within one people-store refresh (~60s) — no commit, no rebuild. Chains (A→B→C) collapse to one hop at load time; a cycle drops the entry and logs it.
- 인물 상세 페이지의 절(`commulingo_person_sections`)은 `ORDER BY sort_order, id`로만 정렬된다. **`sort_order`는 그 절이 다루는 시기의 YYYYMM**(연도만 알면 MM=00: 1898 → `189800`, 1991년 8월 → `199108`)이라는 규약을 쓴다. 그래야 초년기 절을 나중에 써 넣어도 죽음 장면 아래로 밀리지 않는다. 값이 어긋나면 UPDATE 한 번으로 끝나고 배포도 커밋도 필요 없다(people-store 갱신 ~60초). 큐레이터 쪽 짝은 leninbot 저장소 `runtime_tools/commulingo_people.py`의 `_section_sort_order()` — `sortOrder`가 없으면 제목 속 연도를 YYYY00으로 쓰고, 그것도 없을 때만 맨 뒤에 붙인다.
- 러시아어 인명을 새로 등록할 때는 국립국어원 외래어 표기법의 러시아어 표를 따른다. `ш`는 `시`가 기본이고 뒤 모음과 합쳐 `ша`→`샤`, `ше`→`셰`, `ши`→`시`, `шо`→`쇼`, `шу`→`슈`가 된다. **`ш` 뒤에 자음이 오면 `시`를 유지한다**: `Штеменко`→`시테멘코`, `Шпигельглас`→`시피겔글라스`, `Шляпников`→`실랴프니코프`. 따라서 로마자 `Sh...`만 보고 습관적으로 `슈...`라고 쓰지 않는다. 다만 다른 언어에서 온 성이나 한국어 관용 표기가 확립된 이름은 원언어·기존 용례를 확인하고, 이미 인물 카드가 있으면 그 카드 표기를 우선한다. 신규 카드에서는 native name의 `Ш...` 형태와 한국어 이름·별칭을 나란히 대조한다.
- The CommuLingo registries that used to be arrays in code are tables, all read the way the dictionaries are (memory → on-disk snapshot → DB, 60s refresh) and all editable with one statement and no deploy: `commulingo_role_categories` (인물 역할 범주), `commulingo_term_categories` (용어 범주 — migration 115), `commulingo_link_blocklist` (자동링크 예외 — migration 116/117; `kind='phrase'`는 별칭을 품은 문자열, `kind='alias'`는 성 한 단어를 아예 인덱싱하지 않음 — 두 kind 모두 **인물 패스에만** 적용된다), `commulingo_id_redirects` (폐기 id). 용어 쪽 자동링크 예외는 아직 코드다: 복합어 차단은 `data/commulingo/term-linkify.js`의 `BLOCKED_TERM_KO`(예: 전세계→전세), 별칭 제외는 같은 파일의 `NEVER_LINK_TERM_ALIAS_KO` — 단 **표제어는 제외 불가**(소개·개조·전세처럼 표제어가 일반어면 문서 쪽에서 `소<!-- -->개`처럼 HTML 주석 분할로 막는다). data/ 마운트라 파일 수정 후 컨테이너 재시작이면 반영. `commulingo_term_categories` also feeds the curator's tool schema in the leninbot repo, so a category added here is immediately writable by the agent.
- 한국어 시대 표기: 1948년 두 국가가 서기 전의 조선은 `조선`(1897~1910은 `대한제국`), 사람은 `조선인`, 말은 `조선어`다. `한국`은 1948년에 선 남쪽 국가의 이름이라 그 이전 문맥에는 쓰지 않는다(굳어진 예외는 `한국전쟁`). 영어 'Korea'를 시대 구분 없이 옮기면 얄타 회담의 주어가 한국이 되고 식민지 시기 문법서가 한국어 문법이 된다. `그루지야`처럼 일괄 치환할 수는 없다 — 재벌 체제·전세·1987년 체제 같은 현대 남한 항목에서는 `한국`이 맞기 때문이다. 그래서 문장의 연도를 읽어 판정하는 감사를 둔다: `docker exec leninbot-frontend node /app/scripts/audit-korea-terminology.js` (판정 규칙은 `data/commulingo/korean-terminology.js`, 사람이 판단해 남긴 예외는 감사 스크립트의 `KNOWN_OK`). 큐레이터·번역 프롬프트 쪽 짝은 leninbot 저장소의 `agents/commulingo_event_curator.py`, `scripts/commulingo_{events,people}_maintainer.py`, `runtime_tools/archival_translation/core.py`.
