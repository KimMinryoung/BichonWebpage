# CommuLingo 짧은 학습 콘텐츠 설계

작성: 2026-09-12. 상태: 제안, 미구현. 이번 작업 범위는 설계 문서 저장이며 콘텐츠 변경·계측 추가·배포는 포함하지 않는다.

## 1. 출발점과 목표

2026-09-05 04:21~09-12 04:21 UTC Cloudflare 조회에서 명시적 봇·도구를 제외한 강좌 페이지 응답은 115건, 퀴즈 페이지 응답은 208건이었다(HTTP 200). 강좌 문항 요청은 13건(200·304)이었고, 운영 DB의 학습 진도와 문항 응답은 각각 0건이었다. 이는 방문자 수가 아니며 브라우저로 위장한 봇도 제외하지 못한다. 운영자·코딩 에이전트 테스트가 대부분이라는 사용자 해석은 충분히 가능하지만, 현재 집계만으로 외부 이용자의 존재나 부재를 확정할 수 없다.

따라서 이용 부족의 원인이 콘텐츠 품질이라고 단정하지 않는다. 유입 부족, 입구의 선택 부담, 긴 학습 분량, 측정 부재를 별도 가설로 취급한다. 아래 분량·판정 기준도 효과가 입증된 수치가 아니라 소규모 검증을 위한 제품 가설이다.

이 사이트는 필요할 때 찾아오는 사이트이며 매일 접속하는 학습 앱을 전제로 하지 않는다. **한 번의 방문 안에서 개념 하나를 이해하고 새 사례에 적용한 뒤 마칠 수 있게 하는 것**이 목표다. 3~5분 분량을 출발 가설로 삼고 학습 시작·이해·적용을 본다. 다음 날 복습, 간격 반복, 재방문 과제와 알림은 설계에서 제외한다.

## 2. 현재 구조에서 재사용할 것

확인한 코드:

- `views/public/commulingo-index.ejs`: 전체 진도율, 사전 탐색, 최근 업데이트, 이어하기, 퀴즈 입구, 책 목록.
- `routes/commulingo-books.js`, `public/js/commulingo.js`: 책·장 중심 목록, 학습 시작 때 문항 로딩, 개념 설명과 도해, 선택지 피드백, 오답 재시도.
- `public/js/commulingo-schedule.js`: 문항별 로컬 기록과 오답 복습. 한 번도 틀리지 않은 문항은 예약하지 않으며 3연속 정답이면 복습에서 빠진다. 간격 배열에는 1·3·7·14·30일이 있지만 현행 졸업 조건상 실제 정답 후 예약에는 1·3일만 쓰인다.
- `routes/commulingo-progress.js`: 로그인 계정의 진도·응답 동기화. 비로그인 기록은 브라우저에 남으므로 DB만으로 학습량을 알 수 없다.

새로운 짧은 학습은 기존 책·사전·문헌으로 들어가는 입구로 둔다. 기존 장 전체 학습과 ID·진도는 보존한다. 기존 기능을 새 기능처럼 다시 만들지 않는다.

## 3. 제안하는 콘텐츠 구성

| 형식 | 사용자에게 제시할 약속 | 분량과 역할 | 우선순위 |
| --- | --- | --- | --- |
| 질문 하나 배우기 | “월급을 다 받아도 왜 착취라고 할까?” | 상황 → 설명 → 적용, 3~5분 | 첫 구현 |
| 짧은 주제 묶음 | “상품에서 이윤까지, 질문 3개” | 짧은 학습 3개를 순서대로 연결 | 파일럿 통과 후 |
| 원전 더 읽기 | “이 설명의 근거와 한계 보기” | 기존 장·문헌·용어로 연결 | 첫 구현에서 링크 |
| 역사 판단 연습 | “이 사건을 설명하려면 어떤 자료가 더 필요할까?” | 사료 비교와 인과 판단 | 별도 후속 파일럿 |

첫 공개 후보는 정치경제학 3개로 제한한다. 역사 인물·날짜 맞히기와 한꺼번에 섞지 않아 학습 효과를 해석하기 쉽게 한다.

| 질문형 제목 | 한 가지 학습 목표 | 흔한 오개념 | 새 사례에서 확인할 것 |
| --- | --- | --- | --- |
| 상품 가격이 오르면 가치도 늘어날까? | 가치와 시장가격을 구별한다 | 가격 변동을 곧바로 가치 변동으로 본다 | 일시적 품귀만으로 가치 증가를 단정할 수 있는지 |
| 월급을 다 받아도 왜 착취라고 할까? | 노동력의 가치와 노동이 만드는 새 가치를 구별한다 | 착취를 임금 체불과 같은 뜻으로만 이해한다 | 임금이 전액 지급된 경우에도 잉여가치가 생기는 조건 |
| 기계가 좋아지면 이윤도 반드시 늘까? | 생산성 상승에서 기업 이윤 증가를 바로 추론하지 않는다 | 기술 발전이 언제나 같은 크기의 이윤 증가를 보장한다고 본다 | 경쟁·가격·비용 정보가 더 필요한 이유 |

이는 출제 방향이며 출처 검증을 마친 완성 문항은 아니다. 두 번째를 첫 진입 콘텐츠로, 나머지 둘을 선택 가능한 후속 학습으로 편집한다.

## 4. 한 번의 학습 흐름

1. **약속:** 제목, “끝나면 설명할 수 있는 것” 한 문장, 약 4분 표시. 책·난이도 선택이나 로그인 없이 시작한다.
2. **첫 판단:** 짧은 상황과 질문 하나. 선택지 3개와 “아직 모르겠어요”를 제공한다. 성적에 넣지 않고 현재 생각을 드러내는 용도로 쓴다.
3. **핵심 설명:** 3~5문장과 필요한 경우 도식 하나. 용어는 최대 2개만 새로 소개한다. 설명 직후 원문 전문을 읽도록 요구하지 않는다.
4. **적용:** 첫 상황의 수치만 바꾼 문제가 아닌 새 사례 1~2개. 오답이면 그 선택이 놓친 조건을 설명하고, 필요하면 대비 사례를 한 번 더 보여준다.
5. **마무리:** “이번에 구별한 것” 한 문장, 선택 가능한 원전 링크. 기본 종료 지점을 분명히 하고 다음 학습을 자동 시작하지 않는다.

틀려도 강제로 처음부터 다시 풀게 하지 않는다. 성공 상태는 “모두 정답” 대신 “설명까지 살펴봄”, “새 사례에 적용함”을 구분한다. 같은 세션의 재시도 정답을 숙달로 표시하지 않는다.

### 예시: 월급을 다 받아도 왜 착취라고 할까?

- 첫 상황: “어떤 작업장에서 노동자가 하루 동안 새로 만든 가치를 12만 원, 하루 임금을 8만 원으로 가정한다. 임금은 약속대로 지급됐다. 마르크스의 설명에서 잉여가치는 없을까?”
- 선택지: “체불이 없으니 없다” / “새 가치와 노동력 가치의 차이를 살펴봐야 한다” / “제품 가격을 올려야만 생긴다”. 정답은 두 번째이며, 구체적 계산에는 아래 가정이 필요하다.
- 설명: 이 모형에서는 임금이 노동력 가치와 같다고 가정한다. 노동력의 사용으로 만들어진 새 가치가 이를 넘으면 그 차이가 잉여가치다. 이 조건에서 차이는 4만 원이다. 재료·기계에서 이전된 가치는 ‘새로 만든 가치’에 포함하지 않는다. 이 수치는 실증 사례가 아니라 개념 설명용 가정이다.
- 적용: “임금과 노동력 가치가 함께 9만 원이 되고 새 가치는 12만 원으로 유지된다면?”을 먼저 확인하고, 이어 “임금이 전액 지급됐다는 사실만 알려진 다른 작업장의 잉여가치를 계산할 수 있는가?”로 정보의 한계를 확인한다.
- 피드백: 체불 여부, 가치 생산, 판매가격을 구별한다. 잉여가치를 매출에서 임금만 뺀 현금 이익과 동일시하지 않는다.
- 출처 작업: 기존 자본론의 노동력 구매·잉여가치 생산 관련 절에서 정확한 원문과 위치를 확인해 연결한다. 게시 전 검수에서 용어·수치·번역의 정합성을 확인한다.

이론 설명은 “마르크스의 이 모형에서는”처럼 적용 범위를 명시한다. 특정 정치적 결론에 대한 동의를 정답으로 채점하지 않는다. 역사 콘텐츠에서는 확인된 사실, 당사자의 주장, 편집자의 해석을 분리한다.

## 5. 입구와 추천 규칙

공산링고 첫 화면의 학습 영역 상단에 질문형 카드 하나와 “약 4분 · 바로 시작”을 배치한다. 전체 콘텐츠의 0% 진도율은 첫 방문자의 주된 메시지로 쓰지 않는다. 책·사전 탐색은 계속 제공한다.

추천은 설명 가능한 고정 규칙으로 시작한다.

1. 용어·문헌에서 들어왔으면 해당 내용과 직접 연결된 질문을 제시한다.
2. 일반 학습 입구에서는 편집자가 선정한 입문 질문을 제시하고 다른 주제도 고를 수 있게 한다.
3. 현재 방문 중 페이지를 새로고침하거나 돌아온 경우에는 중단한 위치에서 이어갈 수 있게 한다.
4. 학습을 마치면 관련 주제를 선택적으로 제시한다. 모든 주제는 독립적으로 마칠 수 있어야 한다.

첫 파일럿에는 개인화 모델, 실시간 AI 튜터, 연속 출석 보상, 순위표, 알림 발송을 넣지 않는다. 각 상세 용어·문헌에는 직접 관련된 학습이 있을 때만 “이 개념 써보기” 링크를 하나 둔다. 무관한 페이지에 일괄 홍보 카드를 붙이지 않는다.

## 6. 한 방문 안에서 이해 확인하기

- 설명 뒤 새 사례 1~2개로 개념을 적용해 본다. 별도 복습 코스가 아니라 본 학습의 마지막 단계다.
- 틀리거나 모른다고 하면 놓친 조건을 짧게 설명한다. 필요하면 쉬운 대비 사례를 선택해서 볼 수 있게 한다.
- 같은 문제를 다시 맞혔다는 이유로 숙달 표시를 하지 않는다. 첫 적용과 피드백 후 재시도는 구분한다.
- 마지막에 핵심 구별과 원전 링크를 남기고 종료한다. 다시 방문해야 끝나는 과제나 미완료 상태를 만들지 않는다.
- 기존 코드의 간격 복습은 현황 참고일 뿐 새 설계에서 재사용하지 않는다. 기존 기능의 변경·제거는 이번 문서 수정 범위가 아니다.

## 7. 콘텐츠와 기록 모델

정확한 저장 위치·DB 마이그레이션은 구현 때 기존 저장소와 캐시 규칙에 맞춰 확정한다. 파일럿 콘텐츠는 다음 필드를 검증 가능한 형태로 가진다.

| 필드 | 의미 |
| --- | --- |
| `id`, `revision`, `lang` | 짧은 학습의 안정적인 ID, 의미 변경 버전, 언어 |
| `title`, `objective`, `estimatedMinutes` | 질문형 제목, 한 가지 목표, 예상 시간 |
| `conceptIds`, `prerequisiteIds` | 연결 개념과 필수 선행 학습. 첫 콘텐츠는 선행 조건 없음 |
| `sourceRefs` | 기존 문헌·책·절의 참조, 원문 위치, 인용·번역 구분 |
| `opening`, `explanation`, `applicationItems` | 첫 판단, 설명, 같은 방문 안의 적용 문항 |
| `misconceptionId`, `choiceFeedback` | 문항별 오개념과 선택지별 피드백 |
| `nextIds`, `relatedLessonIds` | 다음 짧은 학습과 기존 장 연결 |

문항 ID도 안정적으로 유지하고 답이나 의미가 바뀌면 문항 버전을 올린다. 단순 오탈자 수정은 기존 학습 기록을 무효화하지 않는다. 기존 `lessonId/qNNN` 기록을 새 콘텐츠로 덮어쓰지 않는다. 새 ID 형식은 현행 답안 API의 `qNNN` 검증과 분리하거나 명시적으로 확장한다.

첫 구현은 비로그인 세션 저장으로 현재 방문의 문항 위치·선택 결과·콘텐츠 버전을 보관한다. 새로고침 후 이어가기를 지원하되 저장 불가 환경에서도 학습 자체는 가능하게 한다. 새 콘텐츠의 복습 일정·장기 개인화·계정 동기화는 구현 범위에 넣지 않는다. 기존 책 학습 동기화는 유지한다. 진행 상태와 서버 이용 통계는 목적이 다른 데이터로 취급한다.

## 8. 실제 이용과 효과를 확인하는 방법

조회수로 학습자를 추정하는 문제부터 해결한다. 아래 계측은 구현 제안이며 아직 수집하지 않는다.

| 이벤트 | 발생 조건 | 확인할 질문 |
| --- | --- | --- |
| `learning_offer_seen` | 학습 카드가 실제 화면에 노출됨 | 입구를 본 사람이 있었나? |
| `learning_started` | 사용자가 시작을 눌러 첫 판단 화면에 도달 | 제목과 약속이 시작으로 이어졌나? |
| `learning_answered` | 사용자가 첫 판단·적용 답을 제출 | 열기만 한 것과 실제 조작을 구분할 수 있나? |
| `learning_completed` | 적용과 피드백을 거쳐 마무리에 도달 | 분량이 감당 가능한가? |

필드는 콘텐츠·문항 버전, 단계, 최초 시도 여부, 정오/모름, 활성 학습 시간, 진입 위치 분류, 무작위 방문 식별자로 제한한다. 자유 서술 원문, 계정명, 이메일, IP, 전체 referrer를 분석 데이터에 담지 않는다. 이용 목적을 안내하고 수집 거부를 제공한다. 무작위 식별자는 현재 방문의 흐름을 묶는 데만 사용하며 다른 방문과 연결하지 않는다. 초기 원시 이벤트는 30일 후 삭제하는 안으로 시작한다. 거부·저장 불가 이용은 누락될 수 있음을 집계에 표시한다.

개발·미리보기와 운영 통계를 분리하고, 운영자 브라우저의 명시적 테스트 모드 및 자동화 실행의 테스트 표식을 집계에서 제외한다. 이벤트 ID로 재전송을 중복 제거하고 입력 검증·빈도 제한을 둔다. 인증 없는 이벤트는 조작 가능하므로 외부 사람 수를 확정하는 증거로 사용하지 않는다. 모집한 테스트 참가자의 관찰 기록과 함께 해석한다.

지표 정의:

- 시작률: 카드가 노출된 방문 세션 중 시작한 비율. 노출 수와 분모를 함께 표시한다.
- 첫 적용률: 해설 이후 새 적용 문항의 첫 시도 정답 비율. 해설을 본 같은 문제의 재시도는 제외한다.
- 완료율: 시작한 학습 세션 중 완료한 비율. 이탈이 잦은 단계도 함께 확인한다.
- 효율: 완료자의 활성 시간 중앙값과 같은 방문의 첫 적용 결과를 함께 본다. 숨겨진 탭·긴 비활동 시간을 제외하고 빠른 찍기를 좋은 성과로 간주하지 않는다.

이 지표는 해당 방문의 이해와 조작을 관찰하며 장기 기억이나 지식 정착을 입증하지 않는다. 콘텐츠·언어·버전별 원자료 수를 붙인다. 사람이 적을 때 백분율만 제시하거나 기존 방문 통계와 인과 비교하지 않는다.

## 9. 작은 검증부터 진행하기

### 단계 A — 편집 시제품

위 3개 주제를 완성한다. 각각 첫 판단 1개, 설명 1개, 같은 방문에서 푸는 새 사례 적용 2개를 작성한다. 원문·용어 검토와 초심자 읽기 검토를 거친다. 제작 시 AI를 쓰더라도 공개 전에 사람이 근거와 오답 논리를 확인한다.

모집 가능한 초심자 5~10명에게 모바일로 하나씩 사용하게 하고, 첫 클릭까지의 망설임과 이해하지 못한 문장을 관찰한다. 이는 사용성 탐색이지 학습 효과의 통계 검증이 아니다. 참가자 연락·모집은 별도 실행 작업이다.

### 단계 B — 최소 구현과 운영 파일럿

질문형 입구, 짧은 학습 플레이어, 현재 방문의 이어하기, 최소 이벤트 집계를 구현한다. 기존 렌더링·링크·출처·공통 UI를 재사용한다. 첫 공개 기간은 2주로 잡되 실제 외부 시작이 20건 미만이면 콘텐츠 성공·실패 판정을 보류한다.

초기 검토 목표는 시작 세션의 60% 이상 완료, 완료자의 활성 시간 중앙값 5분 이내, 심각한 개념 오류 0건이다. 이 숫자는 내부 검토 기준이며 교육적 효과의 증명이 아니다.

- 노출 자체가 적으면 유입 경로를 먼저 점검한다.
- 노출은 있는데 시작하지 않으면 제목·학습 약속·입구 위치를 수정한다.
- 시작 후 설명 단계에서 이탈하면 문장과 분량을 줄인다.
- 완료하지만 새 사례를 못 풀면 예시와 오개념 피드백을 고친다.

### 단계 C — 확장 판단

관찰에서 학습 흐름이 이해되고 실제 외부 이용이 확인될 때 짧은 주제 묶음과 역사 판단 연습을 추가한다. 이후 표본을 확보하면 비슷한 난이도의 주제를 기존 장 학습과 짧은 학습에 나누어 해당 방문의 새 사례 적용·소요 시간을 비교한다. 사람이 적은 상태에서 A/B 결과나 효율 개선 수치를 주장하지 않는다.

## 10. 구현 완료 기준과 운영 제약

- 첫 방문자가 로그인 없이 한 가지 학습을 시작·완료할 수 있고, 새로고침 후 이어갈 수 있다.
- 정답·오답·모름·중단·저장 불가 흐름이 동작한다. 타이머나 연속 출석으로 압박하지 않는다.
- 기존 책·사전·문헌 링크와 학습 진도가 유지된다. 새 문항 버전이 옛 기록과 잘못 연결되지 않는다.
- 키보드와 화면 읽기 도구로 조작 가능하며 피드백이 전달된다. [사이트 디자인 기준](design-system.md)의 토큰·공통 컴포넌트·메뉴 경계를 따르고 모바일·데스크톱·다크·라이트를 브라우저로 확인한다.
- 분석에서 테스트 이벤트가 빠지고 중복 전송이 합쳐지며, 거부·미관측 이용의 한계가 표시된다. 새 사례의 첫 시도와 같은 문항의 재시도를 구분하는 검증을 수행한다.
- 콘텐츠 쓰기·캐시 갱신·배포는 [운영 참고](frontend-operations.md)를 따른다. host-mounted 데이터는 즉시 운영에 반영되므로 후보를 별도 검증한 뒤 적용한다.
- 첫 파일럿은 한국어로 제한하고 영어 화면에 한국어 본문을 섞지 않는다. 영어판은 동일한 목표·피드백을 검수한 뒤 공개한다.

먼저 만들 것은 **검수된 짧은 학습 3개와 그 이용을 확인할 최소 흐름**이다. 긴 강좌의 추가 생산은 파일럿에서 무엇이 도움이 되는지 확인한 뒤 결정한다.
