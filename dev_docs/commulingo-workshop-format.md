# CommuLingo 실습 형식(`workshop`)과 플레이어 문항 화면

2026-11-09. 강좌 문항 2,088개가 모두 객관식이고 눈치로 풀리는 문항이 많다는 조사에 따라, 기존 강좌는 그대로 두고 객관식 밖의 활동을 섞는 새 형식을 만들었다. 같은 작업에서 기존 문항 화면의 글씨·보기·해설 배치도 고쳤다. 첫 강좌는 아직 없다(역사 주제로 만들 예정).

## 조사 결과(2026-11-09)

- 정답이 가장 긴 보기인 문항: 『자본』 77%, 입문 강좌(`short-learning`) 66%, 끊어 읽기 34%(한국어).
- 입문 강좌는 장 도입 설명과 낱말이 가장 많이 겹치는 보기가 정답인 문항이 81%다.
- 최근 30일 레슨 시작 50회 가운데 32회가 첫 답 전에 떠났고 12회가 결과 화면에 닿았다(운영자 테스트가 섞였을 수 있다).
- 강좌에 순서·분류·빈칸 같은 활동과 편 끝 정리가 없었다.

## 형식

강좌 문서의 `format: 'workshop'`. 구조는 다른 강좌와 같다: 편마다 `basic` 레슨 하나, `questions[]` 5~8개, 문항 id `qN`. 그래서 진도·오답 재시도·복습·계측(문항 하나가 answered 한 건)은 그대로 동작한다.

- 개념 설명 화면이 없다. 레슨을 열면 첫 문항이 나온다(`skipsIntro`).
- 편에 `takeaway{ko,en}`가 필수다. 결과 화면에 「이번 편에서 구별한 것」으로 나온다.
- `conceptMap`·`conceptBrief`는 요구하지 않는다.

### 문항 유형

| `type` | 필드 | 화면 |
| --- | --- | --- |
| `multiple_choice` | 다른 강좌와 같다(4지선다, `answer: 0`, `choiceFeedback`) | 보기 선택 |
| `order` | `items{ko[],en[]}` 3~6개를 **정답 순서로** 저장. 선택 `itemNotes{ko[],en[]}`(항목마다 하나, 날짜 등) | ▲▼로 옮기고 「확인」. 맞은 자리에 `itemNotes`가 붙고, 틀리면 올바른 순서를 아래에 보인다 |
| `sort` | `groups{ko[],en[]}` 2~3개, `items[{ko,en,group}]` 4~8개(`group`은 묶음 번호, 묶음마다 하나 이상) | 항목을 누르고 묶음 이름을 눌러 넣는다. 다 넣어야 「확인」이 켜진다. 틀린 항목에 「→ 맞는 묶음」 |
| `cloze` | `text{ko,en}`에 빈칸을 `[[낱말]]`로 표시(언어마다 1~3개, 개수 같게). `distractors{ko[],en[]}` 2~4개 | 낱말 상자에서 골라 채운다. 채운 빈칸을 누르면 비워진다 |

공통 필드는 `id`, `points`(2), `prompt`, `explanation`, 선택 `context`(문항 위 한 줄)·`source`. 활동은 한 번의 확인으로 전체가 맞아야 정답이다.

`cloze`의 `source`는 인용(`quote`) 없이 `href`·`label`만 둘 수 있다(지문이 곧 발췌다). `source.href`가 사이트 문헌이고 `kind`가 `reference`가 아니면, `[[ ]]`를 벗긴 한국어 `text`가 그 문헌과 글자 그대로 같아야 한다(` … `로 건너뛸 수 있다). 사이트 문헌을 요약하거나 다듬은 문장으로 빈칸을 내려면 `kind: 'reference'`를 쓴다.

### 검증(`scripts/lib/commulingo-checks.js`)

- 새 유형은 `workshop` 강좌에서만 허용된다(`ctx.workshop`). 유형별 검사는 `checkOrder`·`checkSort`·`checkCloze`.
- 배합(`checkActivityMix`, 규칙 이름 `activity-mix`): 객관식은 레슨 문항의 절반 이하, `order`·`sort`·`cloze` 가운데 두 가지 이상, 객관식 가운데 정답이 가장 긴 보기인 문항은 1/3 이하(언어별).
- 빈칸 낱말은 한국어 14자·영어 30자 이하, 오답 낱말은 정답과 겹치지 않는다.
- 문항 id 재사용 판정(`course-validation.js` `answerSignature`)은 순서·묶음 배치·빈칸 지문을 답으로 본다.
- 쇼츠(`data/commulingo/shorts.js`)는 객관식만 카드로 만들므로 활동 문항은 나오지 않는다.

### 플레이어(`public/js/commulingo.js`)

`renderQuestion`이 유형에 따라 `renderChoices` 또는 `renderActivity`(`renderOrder`·`renderSort`·`renderCloze`)를 부른다. 활동에서는 아래 실행 버튼이 「확인」이 되고(`pendingCheck`), 확인 뒤 「다음」으로 돌아온다. 채점 뒤의 기록·계측·해설은 `settleAnswer` 하나가 맡는다. 순서 목록은 훈련장 연표 덱의 `.commu-drill-order-*` 스타일을 같이 쓴다. 숫자 키 1~4는 객관식에서만 듣는다.

### 강좌 쓰기

`course/<id>` 데이터 문서로 넣는다(`data_document_put`, dry run 먼저). 견본은 `tests/fixtures/commulingo-workshop-sample.json`(파리 코뮌 한 편, 다섯 문항)이다. 작성 기준:

- 문항은 그 문항의 지문·맥락 줄만으로 풀 수 있게 쓴다. 날짜 외우기가 아니라 앞뒤 관계로 순서를 정할 수 있는 사건을 고른다.
- 분류 항목과 객관식 오답은 실제 역사적 입장·조치로 짠다.
- 한국어와 영어를 함께 쓴다.

## 기존 문항 화면에서 바꾼 것

- 문항 글씨: 길이에 따라 크기를 정한다(한국어 70자·영어 150자를 넘으면 `is-long`). 여러 문장으로 된 문항은 상황 설명을 보통 굵기로, 마지막 물음만 굵게 보인다(`setQuestionPrompt`).
- 보기: 기본은 한 줄에 하나다. 보기가 모두 짧고(한국어 22자·영어 44자 이하) 짝수 개일 때만 두 칸(`is-paired`). 세 보기가 두 칸에 걸쳐 하나가 남거나 긴 문장이 좁은 칸에 접히던 것을 없앴다. 올림·그림자 효과를 빼고 답한 뒤 고르지 않은 보기는 흐리게 한다.
- 문항 위의 학습 초점 줄을 뺐다. 그 줄은 장의 결론이라 답을 그대로 알려 주는 경우가 많았다(개념 설명 화면에는 그대로 있다).
- 해설: 고른 보기에 대한 한마디를 먼저, 일반 해설을 그 뒤에 둔다. 상자 안의 상자를 없애고 정오는 왼쪽 선과 「정답/오답」 글자색으로만 나타낸다.
- 모바일에서 실행 버튼이 한 줄을 다 쓴다.

## 검증

- `tests/unit/commulingo-workshop.js`: 견본 통과, 유형별 거부 사례, 배합, id 재사용, 레슨 페이로드.
- `tests/browser/commulingo-workshop.js`: 미리보기에서 견본 레슨을 기존 레슨 자리에 끼워 순서·분류·빈칸·오답 재시도·정리 문장을 360·1280px로 확인한다. `SHOTS=<폴더>`를 주면 단계별 화면을 저장한다.
