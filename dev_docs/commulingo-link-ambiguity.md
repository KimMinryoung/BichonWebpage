# 자동 링크의 의미 중복: 수정과 재발 방안

## 2026-09-08 데이터 수정

`world-war-i`의 1914년 ‘7월 위기’가 `july-days`(1917년 러시아)로 연결됐다.
표제어는 ‘7월 사태’였고 잘못 연결된 표현은 별칭이었다. 한국어·영어 별칭 모두
자동 연결 기본값을 사용했다. 조사 시 용어 976개 모두 link_expressions가 비어 있었다.

실행 기록: `scripts/one-off/fix-ambiguous-term-expressions-20260908.js`.
7개 용어의 모호한 이름을 `search`로 지정해 검색은 보존하고 자동 연결을 중지했다.
7월 사태·소비에트 문화혁명·리가 구호 협정은 표제어도 구체화했다.
나머지 대상은 1917년 러시아 연립정부, 벨로베자 협정, 1988년 제네바 협정,
1954년 파리 협정이다. 구체적인 표제어와 별칭은 자동 연결을 유지한다.
변경 직전 행 전체는 운영 컨테이너 `/tmp/commulingo-ambiguous-terms-1788860337791.json`에 백업했다.

문서 `afghanistan-decisions-1979-1989`에도 ‘제네바 협정’ 별칭이 있어 제거했다.
실제 감사에서 호치민의 1954년 베트남 문맥이 이 아프가니스탄 문서로 연결되는
후보를 확인했다. 문서 패스가 용어보다 먼저 실행되므로 용어만 고치면 남는 오류다.
‘리가 조약’은 현재 문서 패스에서 평화조약으로 연결되지만, 구호 협정의 같은 별칭도
검색용으로 제한해 다른 화면에서 구호 협정으로 잘못 연결되는 것을 예방했다.

이 작업은 위험 표현을 선별해 교정한 것이며 976개 용어 전체의 의미 검수 완료를 뜻하지 않는다.
`audit-link-fires.js`의 수치는 후보 매칭 수이며 실제 렌더링과 다를 수 있다.
이 스크립트는 현재 context 정책, 페이지별 noAutoLink, 자기 항목 제외 등을 완전히
재현하지 않으므로 최종 판단은 운영 렌더러와 브라우저에서 해야 한다.

## 적용 방향 (구체적인 구현 범위는 아래 참조)

1. **표제어·별칭에 같은 등록 규칙 적용.** 특정 사건·제도에는 국가·연도·주체를
   포함한 이름을 요구하고, 일반 개념 항목과 구별한다. 표제어도 안전성 심사를 면제하지 않는다.
2. **검색과 자동 연결 승인 분리.** 신규·수정 표현은 기본 search, 의미가 고유하다고
   검토된 표현만 auto. context는 같은 문맥에 구체적인 identity 표현이 있을 때만 허용한다.
   기존 전체 사전을 한꺼번에 차단하지 말고 감사 결과를 검토해 단계적으로 전환한다.
3. **문서·사건·용어 통합 충돌 검사.** 한국어 NFC·공백 및 영어 대소문자 정규화 후
   표제어↔별칭, 별칭↔별칭을 비교한다. 사전에 경쟁 항목이 없다고 고유한 것은 아니므로
   ‘월+위기’, 일반 정부명, 연도 없는 협정명 등의 의미 검토도 병행한다.
4. **저장 전에 실제 연결 변경 미리보기.** 공통 렌더러로 변경 전후 링크 대상과
   주변 문장·페이지·시기를 보여준다. 정책 없는 신규 표현이나 충돌은 자동 승인하지 않는다.
5. **정기 감사와 회귀 사례.** 1914년/1917년 7월 위기, 베트남/아프가니스탄 제네바 협정,
   서로 다른 국가의 연립정부, 평화/구호 리가 협정을 음성 사례로 저장한다.
   고유한 전체 이름이 정상 연결되는 양성 사례도 함께 검사한다.

현재 `registerAlias`는 같은 사전 내 정확히 같은 문자열의 중복 연결을 막는다.
그러나 사전 간 우선순위와 현실 세계의 동명이의어까지 해결하지는 않는다.
기존 `link_expressions`의 auto/context/search를 활용할 수 있으므로 새 차단 체계를
별도로 만들기보다 등록 경로·검토 도구와 감사 도구를 보강하는 편이 적절하다.

검증: `npm test` 전체 통과. 운영 한국어 및 `/en/commulingo/events/world-war-i`를
Playwright로 열어 `july-days` 링크 0개와 ‘7월 위기’/‘July Crisis’ 본문 보존을 확인했다.
용어 상세의 `July Days (1917, Russia)` 제목도 확인했다. 백업은 호스트 /tmp에도 복사했다.

## 예방 기능 적용 (2026-09-08)

관리자 화면: `/admin/commulingo-links`. 관리자 세션과 허용 IP가 필요하고 쓰기는 CSRF를 검증한다.
문서 편집 화면과 관리자 대시보드에서 접근할 수 있다.

- `commulingo_link_reviews`가 용어·사건·문서의 실제 자동 링크 승인을 관리한다.
  외부 도구가 `linkExpressions.policy=auto`를 직접 저장해도 검토 기록이 없으면 검색 전용이다.
  인물 이름의 기존 전용 문맥 정책은 이번 변경 범위에 포함하지 않았다.
- 표제어와 별칭을 함께 검토한다. 새 표현, 해당 언어의 표제어 변경, 표현 메타데이터 변경은
  승인 서명이 달라져 검색 전용으로 돌아간다. 다른 언어의 변경은 기존 언어 승인을 무효화하지 않는다.
- 초기 이관은 기존 9,637개 표현의 정책을 보존했다. 기존 데이터의 의미 검수 완료가 아니며
  이관 기록에 이를 명시한다. 한영 × 용어·사건·문서 6개 인덱스의 이관 전후 동등성을 검사했다.
- NFC·공백·영어 대소문자를 정규화한 뒤 사전 간 이름·별칭 중복을 검사한다.
  중복 표현의 신규 연결 승인은 거부한다. 일반적인 월별 위기·정부명 등은 무조건 자동 연결을
  거부하며, 이미 승인된 구체적 이름이 같은 본문 단위에 있는 경우의 `context`는 허용한다.
  연도 없는 협정·조약·선언은 주의를 표시하고 검토 근거를 요구한다. 이 휴리스틱이 의미 판정을 대신하지 않는다.
- 정책 저장 전 미리보기는 실제 `renderLinkedContent`를 이용한다. 용어·사건·인물·문서·공개 보고서의
  표현 포함 본문을 찾고 최대 12개 단위를 렌더링해 현재/변경 후 연결을 비교한다.
  자기 항목·페이지별 제외를 적용하며 기존 수동 링크는 보존한다. 학습 콘텐츠는 현재 표본 범위 밖이다.
  미리보기에는 전체 표현 포함 본문 수와 표본 수를 명시한다.
- 미리보기 후 입력 변경은 다시 확인해야 한다. 토큰은 15분 뒤 만료하며 한번만 저장할 수 있다.
  이름·정책·본문·문서 파일·공개 보고서가 바뀌면 오래된 미리보기의 저장을 409로 거부한다.
  동시 승인은 advisory lock으로 직렬화한다. 정책과 변경 전후 이력은 같은 트랜잭션에 기록한다.
- 승인 캐시는 PostgreSQL → 디스크 스냅샷 → 메모리로 제공한다. 조회가 완전히 불가능하고 스냅샷도
  없으면 미검토 표현처럼 자동 연결을 끈다. 저장 직후 강제 갱신하고 다른 프로세스는 약 60초 내 갱신한다.

이름에 붙인 연도 괄호 뒤에서 영어 `\b`가 매칭되지 않던 문제도 수정했다.
이제 `July Days (1917, Russia)`처럼 괄호로 끝나는 전체 이름도 연결할 수 있다.

### 운영과 감사

Migration 178을 관리자 DB 역할로 적용한 뒤 `node scripts/seed-commulingo-link-reviews.js`로
읽기 전용 시뮬레이션을 실행한다. `--apply`로 한 번만 이관하고 배포한다.
테이블에 한 행이라도 있으면 재이관을 거부해 이후 추가된 표현이 자동 승인되는 일을 막는다.
이관 직전 사전 백업은 호스트 `/tmp/commulingo-link-data-before-20260908.dump`,
이전 링크 코드 원본은 `/tmp/commulingo-link-code-before-20260908.tar`,
이미지는 `leninbot-frontend:before-link-reviews-20260908`이다.

`node scripts/audit-commulingo-link-ambiguity.js [--json]`은 읽기 전용 검토 후보 감사다.
`ops/systemd/commulingo-link-audit.{service,timer}`를 grass 사용자 서비스로 설치하면
매일 UTC 04:20 이후 10분 이내에 실행한다. `scripts/audit-commulingo-links-daily`가
검사에 성공한 JSON만 `temp_dev/commulingo-link-audit.json`에 원자적으로 교체한다.
메일·메신저 알림이나 자동 승인은 하지 않는다.

복구 시 이전 이미지와 위 tar의 host data 코드 파일을 함께 복원하고 정규 배포 절차를 따른다.
178 테이블과 검토 이력은 삭제하지 않는다. 코드를 되돌리면 미검토 신규 표현에 대한 제한도
이전 동작으로 돌아가므로, 복구 중 새 항목 등록을 멈추거나 오연결 여부를 별도로 확인한다.

여러 국가의 연립정부·평화/구호 리가 조약과 구체적 이름의 정상 연결 회귀가 포함된다.

`COMMULINGO_ISOLATED_TEST=1`, 명시적 DB_HOST와 `/tmp/` 검토 스냅샷 경로가 필요하다.
독립 PostgreSQL 17의 178 테이블과 합성 코퍼스에서 미리보기·저장·토큰 재사용 거부,

가로 넘침과 브라우저 JS 오류를 검사했다.

운영 확인: `4231775`를 `scripts/deploy --restart`로 배포했고 전체 검사 및 23개 경로,
코드/DB 일치 검사와 컨테이너 health가 통과했다. 운영 한영 세계대전 페이지에서
`july-days` 오연결 0개를 브라우저로 재확인했다. 운영 미리보기는 ‘7월 위기’ 포함
4개 본문에서 기존 검색 전용 정책의 보존을 확인했다.
grass 사용자 감사 타이머를 활성화했고 최초 실행은 성공했다. 첫 보고서는 검토 후보
479개(중복 표현 172개, 일반 이름 주의 339개, 두 집합 중복 있음)를 포함한다.
이 수치는 오류 확정 수가 아니다. 초기 이관 직후 미검토 신규 표현은 0개였다.

### 의미 검토 저장과 반복 감사

초기 `migration-178` 이관은 연결 보존용이며 의미 검토 완료가 아니다. 카탈로그는
현재 source signature와 일치하는 실제 검토를 `semanticReviewed`로 구분한다.
일일 감사는 `needsReview`만 보고한다. 검토된 검색 전용 표현이나, 경쟁 표현을
명시적으로 검색 전용으로 검토한 뒤 선정한 대표 연결은 같은 경고를 매일 재발행하지 않는다.
표현·표제어 변경 또는 대표 연결에 새 미검토/활성 경쟁자가 생기면 다시 감사 대상이 된다.
구조적 risks/collisions는 삭제하지 않으며 관리자 목록에서 계속 볼 수 있다.

서로 겹치는 표현을 승인하려면 경쟁 표현에 유효한 검색 전용 검토가 있어야 한다.
미검토 신규 표현의 기본 search만으로는 경쟁이 해결됐다고 간주하지 않는다.
`previewReviews`/`saveReviews`는 여러 결정을 하나의 최종 정책으로 검증하며, 각 표현별
최대 12개 본문 표본과 실제 렌더러를 유지한다. 공유 본문은 언어별로 한 번만 렌더링한다.
저장은 전체 코퍼스 revision 재검사·advisory lock·단일 트랜잭션으로 현재 정책과
각 표현의 이력을 함께 기록한다. 토큰 재사용, 본문 변경, 동시 승인, 이력 실패는 거부/롤백한다.

검토 결정과 근거는 `scripts/reviews/commulingo-links-20260908.json`, 실행기는
`scripts/review-commulingo-links.js`다. manifest JSON을 stdin으로 주며 기본은 읽기 전용
사전 검증, `--apply`만 저장한다. 기존 표현의 source signature를 대조하고 백업을 남긴다.
원래 후보 479건과 추가 승인된 모호한 별칭 19건·구체적 대체 이름 42건을 포함한다.
역사적 사실 전체의 재감수가 아니라 표현의 의미·연결 대상에 대한 검토다.
