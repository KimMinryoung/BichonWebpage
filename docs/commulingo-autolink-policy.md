# CommuLingo 표제어·별칭과 자동 링크

## 판단 원칙

문자열 길이는 의미를 판정하지 못한다. `스푸트니크`는 위성 이름이고
`소련 우주개발`과 관련되지만 동의어가 아니다. `포스펠로프 위원회`도
그 위원회의 보고서와 다른 대상이다. 관련 항목의 이름을 별칭으로 등록하고
문헌/사건 우선순위로 해결하면 잘못된 대상이 계속 선택된다.

1. 본문에 직접 쓴 링크는 작성자의 명시적 선택으로 보존한다.
2. 등록 표현의 **역할**과 **연결 정책**을 구분한다. 같은 대상의 이름은
   `identity`, 성·약칭은 `short`, 해당 항목으로 설명할 수 있는 관련 개념은
   `related`다. 관련 개념도 검토 후 자동 링크할 수 있으며 동의어로 간주하지 않는다.
3. 같은 표현이 여러 항목을 가리키면 등록 순서로 고르지 않는다. 인물의 성은
   앞서 나온 전체 이름으로 구별할 수 있을 때 연결한다. 충돌하는 이름이 있는
   문단의 모호한 성은 보류하되, 직접 명시된 전체 이름은 해당 인물에 연결한다.
4. 문헌은 서지용 표시 제목에서 별칭을 추측하지 않는다. 실제 저작 제목을
   명시적으로 등록하고, 일반명사와 겹치면 `『현물세』`처럼 제목 표식을 포함한다.
   괄호 안 설명·연도를 사건 별칭으로 자동 추출하지 않는다. NEP 같은 약칭은
   검토한 사건 별칭 목록에 명시한다.
5. 길이 정렬은 기존 각 사전의 정규식에서 한 표현을 부분적으로 자르지 않는
   용도로만 유지한다. **종류를 가로지르는 의미 우선순위로 사용하지 않는다.**

현재 종류별 처리 순서(doc → event → term → topic → person)는 호환성을 위해
유지한다. 이것이 문맥의 의미를 판정한다는 뜻은 아니다. 사전 간 충돌을 모두
정확히 해소한 상태도 아니다. `비밀연설`처럼 원문·개념·사건이 함께 존재하는
경우는 같은 주제를 설명하는지, 특정 읽기 화면에서 어떤 목적지가 필요한지
검토해야 한다. 다음 단계는 종류나 길이의 일괄 우선순위가 아니라 **검토한
표현별 대상/사용 범위**를 데이터로 명시하는 것이다. `sameSubjectEvent`도
확인된 동일 주제에만 사용하고 단순 관련성을 동일성으로 확대하지 않는다.

한국어 성 뒤에는 조사와 검토한 파생 접미사(기·식·파·계·군·적)를 허용한다.
다른 이름의 일부인 체르니셰프스키→체르니셰프 같은 연결은 막는다.
기존 금칙어와 문헌별 `noAutoLink`는 유지한다.

## 등록 표현

`linkExpressions`는 인물·용어·사건·문헌의 선택적 배열이다.

```json
[{"text":"포드","lang":"ko","role":"short","policy":"context"}]
```

- `role`: `identity`(동일 대상), `short`(성·약칭), `related`(설명 가능한 관련 개념).
- `policy`: `auto`(기본 자동 연결), `context`(문맥의 동일 대상 이름이 있어야 연결),
  `search`(검색만 허용).
- 같은 언어·표현의 기존 별칭에 명시적 설정이 우선한다. 나머지 기존 별칭은
  그대로 유지한다. 길이를 보고 역할을 일괄 재분류하지 않는다.
- 인물 API/CLI와 문헌 import/PATCH는 `linkExpressions`를 받는다.
  용어·사건 DB 필드는 `link_expressions`다. migration 166이 세 테이블에
  필드와 제약을 추가하고, 실제 본문에서 확인한 동일 인물의 표기 변형 5건을 등록한다. **배포 전 마이그레이션 적용이 필요하다.**

## 성만 나온 경우

유일한 기존 성 연결은 기본적으로 유지한다. 같은 문단에 다른 이름+성이 있으면
기존 인물에 연결하지 않는다(헨리 포드→제럴드 포드 등). 문단은 HTML 강조 태그를
넘어 이어지되 코드·주석·태그 속성은 문맥에서 제외한다. 인물 소개의 짧은 필드들은
한 문맥으로 판단한다. 브라우저 학습 화면도 서버와 같은 판정 모듈을 쓴다.

동명이인의 성을 새로 연결할 때는 앞선 명시적 이름이 필요하다. 뒤의 로버트 케네디를
근거로 앞의 ‘케네디 행정부’를 로버트에게 새로 연결하지 않는다. 다른 이름을 감지하는
근거는 등록된 이름 및 이니셜이며, 한영 구조화 이름에 확인된 한글 전사 변형도 허용한다.
등록되지 않은 모든 사람을 판별하는 방식은 아니다. 문맥이 없는 오연결은 남을 수 있다.

## 언급과 링크의 통일

`findEntityMentions` 문자열 검색기를 제거했다. 관련 항목과 역방향 관련 리포트는
같은 리포트 본문 렌더링 결과의 실제 링크를 사용한다. 수동 링크도 포함하고,
코드·주석·외부 링크·존재하지 않는 항목은 제외한다. 역방향 링크는 본문에 실제 존재하는
앵커 ID로 이동한다. 감사 스크립트도 공통 렌더링 결과를 사용한다.

## 강제하는 형식

- 표제어·별칭은 HTML이나 HTML entity가 아닌 NFC 일반 텍스트다.
- 앞뒤 공백, 중복 공백, 탭·개행, 숨은 제어 문자를 허용하지 않는다.
- 별칭은 `{ko: [], en: []}` 형태이며 각 언어 배열 안에서 중복되지 않는다.
  자동 링크용 별칭은 최소 두 글자다. 대소문자는 보존한다(약어 오연결 방지).
- 등록 표현의 언어·역할·정책 열거값, 필수 필드, 중복 및 이름 형식을 검사한다.
  검색 전용 표현은 한 글자도 허용한다. DB 직접 입력에도 migration 166의 CHECK를 적용한다.
- 표제어를 별칭 배열에도 한 번 넣는 기존 관행은 허용한다.
- 입력값을 몰래 고치거나 잘못된 배열을 빈 배열로 바꾸지 않고 400 오류를 낸다.

인물 API/CLI와 문헌 import/PATCH에서 검사한다. 문헌의 aliases, noAutoLink,
date, updatedAt는 다른 메타데이터를 수정해도 보존한다. 수동 manifest 수정도
`scripts/smoke-commulingo-alias-validation.js`가 전체 문헌의 형식을 검사한다.

DB 직접 입력은 migration 165의 트리거가 표제어·별칭의 기본 형식을 검사한다.
신규/변경 값에만 적용하며 과거 데이터의 무관한 수정은 막지 않는다. 별칭의
동일 행 중복은 기존 PK가 막는다. **마이그레이션 실행 전에는 DB 강제가 활성화되지 않는다.**
의미가 같은지는 형식 검사로 강제할 수 없으므로 등록 검토와 충돌 감사를 병행한다.

## 검증과 남은 데이터 정리

`node scripts/audit-commulingo-aliases.js`는 로컬 스냅샷을 읽어 등록 형식 오류와
사전 안/사전 간 공유 표현을 출력한다. 충돌은 검토 대상이지 곧 오류라는 뜻은
아니다. 검색 전용/차단 별칭도 포함되며, 코드가 파생하는 인물명과 사건 별칭은
런타임 회귀 테스트로 별도 검증한다. `--strict`는 형식 오류가 있으면 실패한다.
스냅샷은 DB의 복제본이므로 직접 고치지 않는다.

이번 정리에서는 위성/우주개발, 글라스노스트/페레스트로이카, 기관명/문헌명
혼동을 제거했다. migration 165는 좌익반대파에 붙은 통합반대파 별칭을 정리하고
Joint Opposition을 통합반대파 쪽에 등록한다. 기존 snapshot은 DB 반영 후 정상
snapshot 갱신 절차로 갱신해야 한다.
